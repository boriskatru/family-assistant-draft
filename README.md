# Семейный Telegram-ассистент — черновой проект

Python 3.12 · Django · aiogram · OpenAI Agents SDK · PostgreSQL · Docker Compose.

Ассистент для двух пользователей: проекты, дела, события, поездки, оригиналы билетов, чек-листы вещей, напоминания и персональный план. Интерфейс — Telegram. Рабочие данные и журнал действий хранятся на вашем VPS. Google Calendar и LLM подключаются отдельно; команды бота доступны без ключа LLM.

Свободный запрос обрабатывает агент на **OpenAI Agents SDK**: он выбирает инструмент, получает результат, при необходимости выполняет следующие шаги и возвращает итог. Может читать расписание и документы, искать сведения в интернете, получать места и маршруты, затем выполнять разрешённые действия. В режиме `personal` агент выполняет разрешённые действия автономно, включая работу с общими проектами и делами в пределах ваших прав. Любой из двух пользователей может добавить событие для обоих сразу. Второй увидит его в своём расписании и получит уведомление в подключённом личном чате.

## Быстрый запуск на VPS

Ориентир: Ubuntu 24.04 LTS, 2 vCPU, 4 ГБ RAM, 40 ГБ SSD. Команды выполняются из распакованного каталога `family-assistant` под пользователем с правом запускать Docker.

```bash
# Если Docker Engine + Compose ещё не установлены:
sudo bash scripts/install_docker_ubuntu.sh

# Создать .env со случайными секретами, не выводя их в терминал:
python3 scripts/generate_env.py
nano .env

# Собрать образ, создать БД и запустить процессы:
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 migrate bot worker_chat worker_service worker_notifications scheduler
```

В `.env` заполнить `TELEGRAM_BOT_TOKEN` из [BotFather](https://t.me/BotFather), `ALLOWED_TELEGRAM_IDS` — два числовых ID через запятую, `USER_NAMES` — имена в том же порядке. Опционально указать ID общего семейного чата в `SHARED_CHAT_ID`. Не менять сгенерированный `TOKEN_ENCRYPTION_KEY` после подключения Google: он нужен для расшифровки сохранённых токенов.

Каждый пользователь открывает бота в личном чате и отправляет `/start`, затем `/help`. Пользователь без доступа может получить только собственный ID через `/id`. Бот должен быть запущен в единственном экземпляре для одного токена. По умолчанию используется polling: домен, входящие порты и сертификат для Telegram не требуются.

## Уведомления в Telegram

Каждому участнику достаточно один раз открыть личный чат и отправить `/start`. Уведомления работают без Google Calendar и ключа модели.

| Запись | Когда приходит уведомление по умолчанию |
|---|---|
| Созвон | За 1 час, со ссылкой, если она есть у события |
| Отдельное событие-поездка с временем отправления | За 24 часа |
| Поездка с датой начала | Накануне в 08:00 по местному времени участника. Участки этой поездки сохраняют собственные напоминания |
| Другие события, в том числе очные встречи | За 15 минут |
| Персональное расписание | Каждое утро в 08:00 по часовому поясу пользователя |

Напоминания о событиях и поездках учитывают тихие часы. Для события можно попросить другой интервал или отключить напоминания. Параметры утренней рассылки показывает `/settings`, установить время можно через `/settings morning 08:00`. Планировщик проверяет очередь каждые 30 секунд. После простоя он может поставить утренний план в очередь в течение трёх часов.

Сохранённые поездки с датой начала автоматически попадут в рассылку. У существующих событий и серий интервалы уже записаны. Чтобы увидеть, какие из них можно перевести с прежних 15 минут на новые интервалы, выполните на VPS:

```bash
docker compose exec worker_chat python manage.py update_event_reminder_defaults
```

Для применения добавьте `--apply`. Опция `--id UUID` выбирает одно событие или серию вместе с её будущими повторениями. В старой версии явно выбранные 15 минут выглядели так же, как значение по умолчанию, поэтому сначала проверьте список. Команда пропускает отправленные и поставленные в очередь напоминания, наборы с другими интервалами и события, для которых новый момент отправки уже прошёл.

## Первые команды

Ошибки агента и фоновых процессов можно получать в личку: задайте `ERROR_ADMIN_TELEGRAM_ID` своим личным ID из `ALLOWED_TELEGRAM_IDS`. По умолчанию одинаковые сбои подавляются на 10 минут. Отчёты содержат код, этап и безопасную диагностику без текста запросов и ключей. Настройка, проверка доставки и ограничения — [ERROR_REPORTING.md](docs/ERROR_REPORTING.md).

Замените даты, `МОЙ_ID`, `ID_СУПРУГИ` своими значениями; `EVENT_ID` скопируйте из карточки созданного события:

```text
/settings timezone Europe/Moscow
/settings morning 08:00
/task Купить страховку | 2026-11-10 18:00 | 30 | private
/event 2026-11-10 15:00 | 60 | Встреча | Центр | shared | МОЙ_ID,ID_СУПРУГИ
/checklist event EVENT_ID | паспорт; билеты; фотоаппарат
/today
```

`shared` задаёт видимость обоим; участники события указываются отдельно последним полем в примере. Для создания Meet используйте `/call` с таким же форматом после подключения Google. Пришлите PDF/фото, чтобы сохранить оригинал. Файл остаётся личным; `/share document ID_ФАЙЛА shared` открывает его супруге. Все форматы, поездки, повторения и связи с проектами описывает `/help`.

## Редактирование общих записей

Оба разрешённых пользователя могут редактировать события и поездки с `visibility=shared`, независимо от автора: добавлять списки вещей, отмечать пункты, привязывать собственные документы и участки маршрута. Правило действует на уже сохранённые записи без выдачи роли редактора и без миграции данных. Повторения общего события с участием обоих тоже может настроить любой супруг; автор записи сохраняется.

Право редактирования и согласование — разные проверки: перенос, отмена и другие изменения через `update_event` общей встречи по-прежнему требуют согласования второго участника. Чек-листы согласования не требуют. Личные записи и файлы сохраняют отдельные права; для проектов и задач остаются прежние правила редактора/исполнителя.

## Адресная книга и персональный контекст

Адресная книга хранит места, людей и организации, несколько адресов одного контакта, связи с проектами, координаты, ссылки на карты и заметки о проходе/парковке. Общие карточки редактируют оба супруга. Названия «дом»/«у мамы» можно задать отдельно каждому. Контакт в справочнике не получает доступ к боту.

Напишите боту «сохрани место …», «найди адрес …» или воспользуйтесь `/places`, `/contacts`, `/place`, `/contact`. Геолокацию можно сохранить командой `/saveplace Название | shared` в ответ на точку Telegram. Карточки создаются только из переданных вами данных. Подробные сценарии — [ADDRESS_BOOK.md](docs/ADDRESS_BOOK.md).

Персональный профиль добавляется к системному промпту из файла на VPS. В архиве лежит **пустой** `config/personal_context.example.md`. Чтобы создать рабочий файл, выполните:

```bash
sudo python3 scripts/init_personal_context.py
sudo nano private/personal_context.md
```

Заполненный `private/personal_context.md` исключён из Git и Docker-образа; файл подключается только для чтения и перечитывается на каждом новом запросе. Инструкция и настройки — [PERSONAL_CONTEXT.md](docs/PERSONAL_CONTEXT.md).

## Подключение функций

| Функция | Что настроить |
|---|---|
| Многошаговый агент | `LLM_API_KEY`, `LLM_MODEL`, `AGENT_ENABLED=1`; адрес `LLM_BASE_URL` должен поддерживать Responses API и function tools |
| Память диалога | `AGENT_HISTORY_USER_LIMIT=50` включает текущий запрос и до 49 предыдущих сообщений этого пользователя в том же чате вместе с ответами бота |
| Кэш модели | `LLM_PROMPT_CACHE_TTL=30m` для поддерживаемых моделей OpenAI, включая GPT-6 Luna и GPT-6.1 Terra. История хранится на VPS, а OpenAI может повторно использовать общую начальную часть запросов |
| Интернет-поиск | Встроенный web search OpenAI с тем же ключом; для другого поискового провайдера — `BRAVE_SEARCH_API_KEY` |
| Места и маршруты | `GOOGLE_MAPS_API_KEY`; включить Places API (New) и Routes API, см. [DEPLOY.md](docs/DEPLOY.md) |
| Голосовые | Дополнительно `LLM_TRANSCRIPTION_MODEL`, поддерживающая audio transcriptions |
| Распознавание изображений/PDF через модель | `LLM_DOCUMENT_MODEL`; реквизиты помечаются как требующие проверки |
| Google Calendar / Meet | Домен, профиль `web`, Google OAuth client; см. [DEPLOY.md](docs/DEPLOY.md) |
| Закрытый общий чат | `SHARED_CHAT_ID`, бот добавлен в эту группу; обращение командой или ответом боту |
| Ошибки в личном чате администратора | `ERROR_ADMIN_TELEGRAM_ID`, один разрешённый пользователь; `/start` в личке. Интервал повторов — `ERROR_ALERT_COOLDOWN_SECONDS` |

Без удалённой модели текст PDF извлекается локально в пределах установленного лимита; фото сохраняется оригиналом без OCR. Поиск по сохранённым документам выполняется локально с проверкой доступа. Карты работают после настройки API; фактические задержки рейсов не отслеживаются. Полный перечень готовности и ограничений — [STATUS.md](docs/STATUS.md).

Пример запроса после загрузки билета: «Найди мой билет на поезд, прочитай время отправления, проверь маршрут от дома до вокзала и добавь личное событие выезда с запасом 30 минут». Агент уточнит отсутствующий адрес или неоднозначный билет; при недоступном API сообщит, какой шаг не выполнен. `/agent` показывает режим, `/agent autonomy read_only` отключает изменения агентом, `/agent autonomy personal` возвращает автономные личные действия. Явные команды бота доступны в обоих режимах.
