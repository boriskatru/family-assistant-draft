# Адресная книга

Справочник состоит из мест и контактов (людей или организаций). У контакта может быть несколько мест; место можно связать с несколькими контактами и проектами. Друзья и сотрудники из справочника не получают доступ к боту. Интерфейс — только Telegram.

## Первое заполнение

Точные адреса в архиве не заполнены. Напишите боту, например:

- «Создай общее место „Мастерская“ по адресу …».
- «Запомни это место как „дом“ для меня».
- «Создай контакт … и привяжи к нему эти два адреса».
- «Добавь встречу завтра в 12 в мастерской».
- «Посчитай дорогу от мастерской до офиса на машине к 15:00».

Для естественного языка нужны включённый агент и модель. Прямые команды ниже работают без модели. Имена, текущие сроки и рабочие проекты можно описать отдельно в персональном контексте, см. [PERSONAL_CONTEXT.md](PERSONAL_CONTEXT.md).

## Команды

```text
/place Мастерская | полный адрес | shared
/place Дом | - | private
/place Офис | - | shared | https://example.org/map
/contact Имя | person | private | телефон | email
/contact Компания | organization | shared
/places мастерская
/contacts компания
/show place ID
/show contact ID
/place_edit ID | новый полный адрес
/place_confirm ID
/alias ID | дом
/unalias ID | дом
```

Знак `-` означает незаполненное поле. Ссылка на карту сохраняется как ссылка, без автоматического извлечения точного адреса. Для расчёта пути нужны координаты либо подтверждённый полный адрес; после заполнения командой `/place` его можно подтвердить через `/place_confirm ID`. В естественном языке агент может сразу сохранить полный явно указанный вами адрес как подтверждённый. Неполные карточки — например, только город — сохраняются для последующего уточнения.

Отправьте точку или место через вложение «Геопозиция» Telegram, затем ответьте на него:

```text
/saveplace Мастерская | shared
```

Ответ обычным текстом, например «Сохрани как мастерскую», также передаёт координаты агенту. Получение точки само по себе не создаёт карточку и не означает, что вы сейчас там находитесь. Для следующей страницы списка используйте `/places запрос | 20` или `/contacts запрос | 20`; номер смещения показывается в ответе.

Общие названия в `aliases` принадлежат карточке. `/alias` и инструмент `set_place_alias` создают названия текущего пользователя: «мама» у супругов может указывать на разные места. Несколько совпадений возвращаются как неоднозначный результат — бот должен уточнить выбор. Уточнение не заменяется выбором первого адреса.

## Права и связи

- `private`: чтение и редактирование владельцем; `shared`: чтение и редактирование обоими разрешёнными пользователями. Видимость меняет владелец через `/share place ID private|shared`, `/share contact ID private|shared` или просьбу агенту.
- В настроенном общем чате доступны общие карточки и собственные личные карточки отправителя. Чужие личные карточки недоступны. Ответ на запрос владельца виден всем участникам группы, но видимость карточки в БД не меняется. Связь с общим контактом или проектом сама по себе не открывает личные данные.
- При изменении агент передаёт актуальную версию карточки. Если её уже изменили, нужно прочитать свежую версию. Общие карточки не требуют согласования второго супруга.
- Для сохранения события агент передаёт `place_id`; для участка поездки — `origin_place_id` и `destination_place_id`. Правила согласования изменений самой встречи сохраняются.
- Личное место нельзя автоматически скопировать в общее событие/участок. Сначала явно откройте доступ к месту или укажите самостоятельный адрес события.

## Адреса встреч и маршруты

Событие и участок поездки хранят ссылку на место и копию адресных данных на момент выбора. Переезд меняет карточку, но не адрес прошлых или уже запланированных встреч. Чтобы обновить адрес встречи, попросите бота выбрать актуальное место для этого события. Изменение адреса свободным текстом отсоединяет старую ссылку на карточку. Перенос адреса непосредственно в Google Calendar также отсоединяет прежнюю карточку при импорте.

В снимке нет телефонов, заметок о проходе и парковке. Видимость снимка определяется событием: если место позднее сделано личным, уже скопированный адрес общей встречи остаётся частью этой встречи. При необходимости измените доступ и к самой встрече.

Для нового маршрута инструмент `route_places` использует текущие координаты/подтверждённый адрес выбранных мест. Для уже согласованного события агент использует сохранённый снимок через `route_between`. Расчёт длительности требует настроенного `GOOGLE_MAPS_API_KEY` и Routes API. Хранение адресов и выдача ссылок на карты работают без него. Телефоны, email и инструкции о проходе в запрос маршрута не включаются.

Справочник не отслеживает текущее местоположение и не задаёт автоматически старт утренней поездки. Агенту нужна указанная вами отправная точка или актуальная договорённость. Обновление не меняет прежние `/settings home` и `work`; их можно перенести в карточки отдельной просьбой боту.

## Обновить существующий VPS

После распаковки нового архива в рабочую копию и отправки изменений в GitHub дождитесь успешного CI с PostgreSQL. На VPS:

```bash
cd ~/family-assistant-draft
git pull --ff-only
sudo python3 scripts/init_personal_context.py
sudo nano private/personal_context.md
docker compose build bot
docker compose stop bot worker_chat worker_service worker_notifications scheduler
docker compose up -d
docker compose ps
docker compose logs --tail=60 migrate bot worker_chat
```

Перед переходом сохраните актуальную резервную копию БД. Сервис `migrate` автоматически применяет `0003_address_book`; существующие события, поездки и файлы сохраняются, справочник первоначально пуст. Установка дополнительных Python-пакетов не нужна. Не используйте `down -v`: это удаляет данные PostgreSQL и файлы.

Если у вас настроен web-профиль, обновите также его службы привычным способом; приведённая команда запускает базовый режим Telegram polling. Персональный файл остаётся на VPS при последующих `git pull` и пересборках. Резервирование БД включает адресную книгу; `private/personal_context.md` нужно сохранять отдельно защищённым способом.
