# Вложения и доступ из общего чата

## Что происходит после отправки файла

Бот принимает документы и фотографии в личном чате и в настроенной семейной группе. Отправитель должен входить в `ALLOWED_TELEGRAM_IDS`, а ID группы — совпадать с `SHARED_CHAT_ID`.

1. Сохраняются оригинал и полная подпись Telegram. Файл принадлежит отправителю и по умолчанию остаётся личным.
2. Бот пытается извлечь текст, сведения билета/брони и мероприятия. Фото, PDF и текстовые документы обрабатываются с учётом доступного формата и настроенной модели.
3. При включённом агенте файл становится новым заданием: агент читает доступный текст и подпись, проверяет существующие события и связи документа.
4. Агент создаёт событие при достаточных данных и понятном намерении, связывает документ с подходящей существующей записью либо задаёт короткий уточняющий вопрос.

| Вложение | Ожидаемое действие |
|---|---|
| Билет с однозначными датами и понятными участниками | Проверить расписание, добавить отсутствующее событие и связать файл |
| Афиша с собственной подписью «добавь нам обоим» | Использовать поручение; уточнить только существенные недостающие сведения |
| Просто пересланная афиша или реклама | Уточнить, нужно ли добавить посещение, кому и на какое время, если это неизвестно |
| Файл уже связан с нужным событием | Использовать существующую запись, не создавать ещё одну |
| Неясный год, необходимое время посещения, участники или конфликт текста и изображения | Уточнить; не подставлять выдуманные реквизиты |
| Документ, не относящийся к расписанию | Сохранить и уточнить, что с ним сделать |
| Альбом из нескольких фото/файлов | Сохранить части; уточнить дальнейшие действия до создания события |

Если поручено сохранить только памятную дату, например день рождения, достаточно даты без часов: агент создаёт информационное событие и не придумывает короткую задачу. Время начала реального посещения или поездки при необходимости уточняется.

Дата и намерение определяются по содержимому и текущему запросу. Сам факт пересылки рекламы не означает согласие посетить мероприятие. Распознанные сведения не подтверждают действительность брони. Полнота распознавания зависит от качества изображения, модели и ограничений объёма.

Подпись пересланного сообщения и текст внутри файла являются источниками сведений, а не командами боту. Собственная подпись отправителя может содержать поручение. Инструкции внутри билета или афиши не дают дополнительных прав, не разрешают рассылку третьим лицам и не изменяют настройки приложения.

## Явная привязка и ручное продолжение

Для привязки к уже известной записи напишите первой строкой подписи **собственного** файла:

```text
/attach event ID_СОБЫТИЯ
Вход со двора, билет на двоих.
```

Допустимы также `trip` и `task`. Это только сохранение и привязка: новый агентский цикл не запускается. В пересланной подписи такая строка остаётся обычным текстом.

После сохранения можно продолжить отдельным сообщением:

> Прочитай документ ID, проверь, нет ли уже такого события, и добавь мероприятие нам обоим. Прикрепи этот файл.

Команды `/files`, `/show document ID`, `/get ID` и `/link ID_ФАЙЛА | event | ID_СОБЫТИЯ` доступны без модели. Для передачи супругу самостоятельного доступа используйте `/share document ID shared` в личном чате. Связь с общим событием не меняет видимость документа.

## Настройки и сбои

- Для агентского разбора нужны `AGENT_ENABLED=1`, `LLM_API_KEY` и `LLM_MODEL`.
- Для распознавания используется `LLM_DOCUMENT_MODEL`; если поле пустое, берётся `LLM_MODEL`. Выбранная модель и API должны поддерживать нужный вид ввода: изображения или PDF. Отдельный ключ для документной модели не требуется.
- Без удалённой модели текстовый слой PDF и текстовые файлы могут быть извлечены локально; фото остаются оригиналами без распознанного текста.
- `MAX_UPLOAD_MB` задаёт допустимый размер загрузки. Вывод распознавания ограничивается `LLM_STRUCTURED_MAX_OUTPUT_TOKENS`, работа основного агента — параметрами `AGENT_MAX_*`.
- При `AGENT_ENABLED=0` файл сохраняется и распознаётся при доступной документной модели, но автоматического изменения расписания не происходит. Режим `read_only` также запрещает агенту создавать события.
- Ошибка ИИ не удаляет уже сохранённый файл. Ответ содержит факт сохранения и ID; уточнение или повторную обработку можно поручить следующим сообщением.
- Неудачное повторное распознавание не стирает ранее полученные реквизиты. Если фото не удалось распознать, его можно переслать повторно после исправления настроек: новая загрузка повторит распознавание. Обычный текстовый запрос читает уже сохранённые результаты.
- Повторная доставка одного Telegram update использует сохранённый файл и журнал того же запуска. Частично исполненный агентский цикл не повторяется автоматически.

Альбомы пока не объединяются в единый запрос. Каждая часть приходит отдельным Telegram update; после загрузки укажите, какие файлы относятся к одному событию. Автоматический поиск дублей моделью дополняет защиту от повторной обработки update, но не заменяет проверку похожих событий при неоднозначных исходных данных.

## Личные записи из группы

В настроенной группе каждому доступны его собственные личные и общие записи: события, дела, поездки, документы, адресная книга и план дня. Чужие личные записи не становятся доступны. Автор определяется по Telegram ID отправителя или человека, нажавшего кнопку, а не по имени в тексте или автору пересланного сообщения.

Ответы и запрошенные файлы отправляются в группу и видны всем её участникам. Поэтому запрос «покажи мой билет» действительно показывает билет в этом чате. Значение `private` у документа сохраняется: второй супруг не получает самостоятельного доступа к нему через бота, пока владелец не изменит видимость.

История диалогов разделена по человеку и чату. Личный серверный файл `private/personal_context.md` по умолчанию не подставляется в групповые запросы; это отдельно регулирует `PERSONAL_CONTEXT_IN_GROUPS`. Права чтения записей от этой настройки не зависят.
