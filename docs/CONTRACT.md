# Internal implementation contract

Project package config, app assistant. Django sync ORM. Models in assistant/models.py are authoritative. Python 3.12, Django 5.2, aiogram 3, httpx, psycopg, cryptography, dateutil, pypdf. venv ../.venv_family. Tests pytest with config.settings, SQLITE_PATH default for tests; production PostgreSQL DATABASE_URL.

Root owns models/settings/services.py/queue.py/runtime.py and management runworker/runscheduler/bootstrap_users. Others must not edit these; send requests.

Services functions (sync; user is Person, shared_context excludes all nonshared content):
- visible(queryset,user,shared_context=False,include_busy=False) -> queryset
- can_view(obj,user,shared_context=False)->bool; can_edit(obj,user)->bool; safe_event(event,user,shared_context=False)->dict (busy redaction)
- create_project(user, **data), create_trip(user, **data), create_task(user, **data), create_event(user, **data) -> model. Fields models match; participants accepts list of Person UUID strings. Dates can be ISO strings; owner enforced from user, links ACL enforced. data participants omitted default owner. create_event accepts remind_minutes list default [15], meeting bool optional and checklist list optional. An event attended by both authorised users is confirmed on creation by either participant. Creating an event attended only by the other person still requests their approval.
- update_event(user,event_id,changes, expected_version=None)-> Event or ActionRequest, cancel via status cancelled; move shared requires other person approval. approve_action(user,request_id,approve=True)->event
- complete_task(user,task_id)->Task, after_completion handled via recurrence module.
- make_checklist(user,parent_type,parent_id,text)->Checklist; set_checklist_item(user,item_id,checked:bool)->ChecklistItem
- save_document(user,filename,content:bytes,mime_type,**metadata)->Document; link_document(user,document_id,parent_type,parent_id)->Document
- get_entity(kind,id,user,shared_context=False)->model; kind project/task/event/trip/document/checklist
- context_for(user,shared_context=False)->dict bounded readable context for LLM
- execute_action(user, action:dict, shared_context=False)->dict {text, entity_type?, entity_id?, request_id?}; dispatcher of validated operations
- enqueue(kind,payload,dedup_key,run_at=None,queue='service') in assistant.queue -> Job

Telegram bot agent owns assistant/bot.py, management/commands/runbot.py, tests/test_bot.py. Implement async process_update(payload) (safe durable updater root queues Telegram updates). Default long polling with custom ingestion handler that enqueue('telegram_update',{'update_id':id},...,queue='chat') then returns; update_id DB table unique. Root worker calls asyncio.run(bot.process_update(payload)); aiogram send via Bot per operation/context. Also HTTP webhook will queue same. Bot command `/id` may show sender's own ID without granting access. For commands and actions use sync_to_async wrappers around service calls. Bot can enqueue outgoing messages with assistant.queue.enqueue('telegram_send',{'chat_id':..,'text':..,'reply_markup':..},dedup,..). process_update returns None.

Google agent owns assistant/integrations/google.py, assistant/google_views.py, tests/test_google.py; implement authorization_url(person)->str, oauth_callback(request)->HttpResponse, sync_all()->None, sync_event(event_id,create_meet=False)->None, list_calendars(person)->list, select_calendar(person,calendar_id,role='personal',writable=True)->CalendarSource. Tokens Fernet from settings.TOKEN_ENCRYPTION_KEY; GOOGLE_CLIENT_ID/SECRET/REDIRECT_URI; all oauth state hash one-use expiration. settings.PUBLIC_BASE_URL. Never import private event to shared calendar or grant other user edit implicitly. Conflict preserve and report. Scalar events expansion okay documented recurrence limitations; no silent unsupported claims.

Planning agent owns assistant/planning.py, assistant/recurrence.py, tests/test_planning.py, tests/test_recurrence.py. Implement build_daily_plan(person,day)->DailyPlan; render_daily_plan(person,day)->str; accept_plan(person,day)->list[Event] with availability recheck; materialize_recurrences(now=None)->int and on_task_completed(task)->Task|None; check_trip(trip)->list[dict]. Plan items JSON ISO times, task_id/event_id, title, state/reason. All privacy including busy_only and participants distinction, no proposed block calendar until accepted. Profile keys work_start/work_end (HH:MM), work_days [0..4], sleep_start/sleep_end, max_daily_minutes, break_minutes, min_block_minutes, transport_mode, locations dict; later complex profiles not implemented must doc limitations. Services will call recurrence.on_task_completed after saving done inside transaction. recurrence can import services locally inside functions.

LLM agent owns assistant/integrations/llm.py, tests/test_llm.py. Implement interpret(user,text,shared_context=False,history=None)->dict action. Requests OpenAI Responses via httpx; settings LLM_API_KEY/MODEL/BASE_URL (base default https://api.openai.com/v1), optional audio transcription and document extraction. No actual API calls in tests. Action schemas match execute_action service actions: create_project/create_trip/create_task/create_event/update_event/complete_task/make_checklist/list/answer. Root services execute supports args dict. Unknown model provider disabled fallback is commands. Require confirmation of LLM-generated writes via pending conversation + button (bot agent). Use existing allowed context only; answer must not imply executed. Reply format {'action':str,'args':dict,'reply':str}; force strict JSON schema or validate pydantic. No model-generated arbitrary HTTP or SQL. transcription function transcribe(content,filename)->str optional adapter, extraction function extract_document(content,mime_type,filename)->dict optional. Bots integrate imports.

Ops agent owns Dockerfile, compose.yaml, .env.example, .dockerignore/.gitignore, scripts/, README.md, docs/DEPLOY.md, docs/STATUS.md, .github/workflows/tests.yml; coordinate models/behavior via code as it appears. Default bot long polling no inbound ports; optional HTTPS profile caddy+web Google OAuth. Commands: bootstrap_users, runbot, runworker --queue=chat/service/notifications, runscheduler, tests pytest. Root service sends notifications via notifications queue; service Google sync; chat queue process updates. APP_UID 10001 persistent volume init handled safely. Root will create requirements.txt/lock via pip freeze. Need scripts for generate env (random secrets), backups, installation and optional webhook. No actual external writes.
