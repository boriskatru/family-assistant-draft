# Персональный контекст семьи

В проекте есть пустой шаблон `config/personal_context.example.md`. Общие правила бота остаются в исходниках. Сведения о семье заполняются отдельно на VPS в `private/personal_context.md` и добавляются к системным инструкциям основного ассистента при каждом новом запросе.

## Настроить на VPS

Из каталога проекта выполните:

```bash
sudo python3 scripts/init_personal_context.py
sudo nano private/personal_context.md
```

Скрипт создаёт **пустой** файл, а при повторном запуске сохраняет уже записанный текст. Он выставляет владельца `root`, группу `10001`, права `750` на каталог и `640` на файл: приложение из Docker может читать, изменять файл можно на сервере. Сохраните текст в UTF-8.

В файл можно вписать, кто такие пользователи, чем занимаются, названия и разговорные обозначения проектов, предпочтения в общении и планировании. Точные адреса удобнее хранить в адресной книге; сроки и состояние дел — в БД. Содержимое профиля не создаёт событий само по себе.

## Параметры .env

```dotenv
PERSONAL_CONTEXT_FILE=/app/private/personal_context.md
PERSONAL_CONTEXT_MAX_CHARS=20000
PERSONAL_CONTEXT_IN_GROUPS=0
```

Эти значения действуют и без добавления переменных в существующий `.env`. По умолчанию файл используется в личных диалогах обоих разрешённых пользователей. Если весь текст предназначен также для общего семейного чата, установите `PERSONAL_CONTEXT_IN_GROUPS=1`. Это один общий профиль, а не отдельное секретное хранилище каждого супруга. Для отключения задайте `PERSONAL_CONTEXT_FILE=`.

Compose подключает каталог `private/` к `/app/private` только для чтения. После первого обновления Compose пересоздаст контейнеры с этим подключением. Последующие изменения **содержимого файла** подхватываются со следующего запроса; пересборка и перезапуск не требуются. Изменения `.env` применяйте через `docker compose up -d`.

Пустой или отсутствующий файл допустим: бот продолжит работу с основными инструкциями. Некорректная кодировка, недостаточные права чтения или превышение лимита дают понятную ошибку без публикации текста профиля. Лимит задаётся в символах; сам профиль также расходует контекст модели и общий бюджет запроса.

## Обновления и резервирование

Каталог `private/` исключён из Git и Docker build context. `git pull` и пересборка образа сохраняют заполненный файл на VPS. Не записывайте личные сведения в отслеживаемый шаблон `config/personal_context.example.md`.

Существующая резервная копия БД/медиа не включает этот каталог автоматически. Храните защищённую резервную копию `private/personal_context.md` отдельно, вместе с конфигурацией сервера. Профиль передаётся выбранному провайдеру модели как часть системного запроса.
