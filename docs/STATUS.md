# Статус черновой реализации

Проект реализует рабочее ядро ТЗ 1.1 и расширение с многошаговым агентом; это черновая версия для проверки на двух аккаунтах. Бизнес-модель частично сгруппирована: профиль/пассажиры/элементы дневного плана хранятся в JSON, а общие права — в моделях и сервисах. Это не обещание полной приёмки всех сценариев ТЗ.

## Что проверять в первой версии

| Область | Реализация / граница |
|---|---|
| Telegram | Личные чаты двух разрешённых пользователей; настроенная закрытая группа с доступом отправителя к собственным личным и общим данным; команды, кнопки и вложения. Polling по умолчанию |
| Диагностика | Коды ошибок в ответах и безопасные технические отчёты одному настроенному пользователю в личку; подавление повторов, проверка получателя перед отправкой |
| Проекты и задачи | Создание, чтение, редактирование проектов и задач, выполнение/возврат, преобразование ошибочной задачи в событие, связи с проектами/поездками; общие задачи редактируют оба супруга |
| События | События с временем и на дату, ежегодные повторения; отдельные признаки занятости и нагрузки; редактирование участников; создание на двоих и немедленное редактирование, перенос и отмена общих событий любым супругом |
| Чек-листы | Создание, добавление/изменение/удаление пунктов, количество, исполнитель и отметки |
| Документы | Сохранение оригинала до распознавания; текст PDF/DOCX/XLSX/текстовых файлов и распознавание изображений/смешанных PDF; агент читает файл с подписью, проверяет существующие записи и создаёт событие либо уточняет дальнейшие действия |
| Напоминания | Сохранённая очередь, отдельный worker отправок, повторы, восстановление заданий; возможны дубли при неопределённом ответе внешнего API |
| План дня | Предложения по свободным окнам и настройкам; информационные даты не занимают время; нейтральный счётчик отложенных дел и отдельные срочные проблемы; принятие с повторной проверкой доступности |
| Повторения | Календарное правило, сменный цикл и интервал после завершения; горизонт материализации 180 дней; изменение/остановка будущих локальных повторов; общие серии редактируют оба супруга |
| Google | OAuth, выбранные календари, импорт/экспорт отдельных событий, обнаружение конфликтов и Meet; нужны реальные аккаунты/ключи |
| Агент | OpenAI Agents SDK: многошаговый цикл выбора инструментов, наблюдений и действий; личный режим автономности или read_only; ограничение шагов/времени, локальный журнал |
| БД и документы | Актуальные разрешённые запросы через ORM, лексический поиск по тексту, чтение частями; произвольного SQL и векторного индекса нет |
| Интернет | OpenAI web search или Brave; чтение публичных страниц с источниками и ограничением объёма |
| Карты | Google Places API (New) и Routes API: места, длительности и расстояния после настройки ключа |

Задачи, проекты, события и поездки с `shared`, а также чек-листы событий/поездок, могут редактировать оба разрешённых супруга независимо от автора; старые записи получают это право без миграции. Настроить повторения события с участием обоих может любой из них. Описание, адрес, ссылка, время и отмена общего события меняются сразу по поручению любого из супругов. Создание события только для другого человека всё ещё требует его подтверждения.

Видимость `shared` и участие — разные поля: общий доступ не записывает второго пользователя в участники автоматически. Их Telegram ID можно явно передать в `/event`, `/call` или `/trip`. Общая поездка также не открывает личные файлы: доступ к документу задаётся отдельно через `/share document ID shared`.

Адресная книга поддерживает личные/общие места и контакты, поиск, псевдонимы каждого пользователя, геолокацию Telegram и снимки адресов в событиях/участках поездки. Персональный системный контекст загружается из отдельного серверного файла. Точные адреса, координаты и сведения семьи в дистрибутиве не заполнены.

События на дату создаются без начала/окончания по часам. По умолчанию они информационные (`blocks_time=false`), с напоминанием в 09:00 в первый день; для занятых дней доступно `blocks_time=true`. В Google Calendar этот признак соответствует «Свободен/Занят». Существующие записи при миграции сохраняют прежнюю занятость. Многодневные события показывают даты начала и окончания, а не только часы. Подробности и исправление старых задач — [TASKS_AND_DATES.md](TASKS_AND_DATES.md).

## Что не считать завершённым продуктом

- Адресная книга не отслеживает ваше местоположение. Ссылка на карту сохраняется, но сама по себе не считается проверенными координатами. Автоматического обхода адресов и глобальной оптимизации всех поездок нет; агент может последовательно рассчитать необходимые участки через настроенные карты. Существующие поля `/settings home` и `work` сохраняются, но автоматически не импортируются в справочник.
- Преобразование задачи в событие требует явного поручения. Преобразование активной серии задач целиком и задач с незавершёнными зависимостями не поддерживается; бот сообщает о препятствии. Исходные записи на сервере не исправляются автоматически при установке обновления.
- Локальные серии поддерживают изменение будущей части; для внешних серий Google: внешние серии безопаснее менять в Google Calendar. Импорт внешних серий разворачивается в отдельные вхождения на ограниченном горизонте.
- Локальные повторы экспортируются в Google отдельными событиями.
- Google импортирует окно от 30 дней назад до 180 дней вперёд и ежедневно обновляет горизонт. Google-private событие в общем источнике остаётся личным в приложении и автоматически не изменяется/не удаляется; для редактирования ботом перенесите его в личный Google-календарь.
- Автоматическая отправка приглашений внешним email-адресатам не включена.
- Изменения, внесённые непосредственно в Google Calendar, импортируются без дополнительного подтверждения. Правки общих событий через бота также применяются сразу. Импорт общего календаря назначает обоих разрешённых супругов, кроме личных Google-записей. Явные последующие изменения состава участников сохраняются; старые импорты исправляются командой repair_schedule_state --apply.
- Карты требуют отдельного ключа Google Maps Platform, включённых API и доступного покрытия. Ответ API о пути — оценка, а не гарантия прибытия. Задержки авиарейсов и изменения транспорта отдельным источником не отслеживаются; проверка стыковок по ручным буферам не гарантирует правила конкретного перевозчика.
- Веб-чтение работает с доступным публичным HTTP-контентом. Полноценного браузера, выполнения JavaScript, входа на сайты, обхода paywall или автоматической покупки нет. Содержимое внешних источников может быть неполным или ошибочным.
- Документный поиск лексический и ограничен извлечённым текстом и допустимым объёмом файла. Для OCR нужна модель с поддержкой изображений; используется `LLM_DOCUMENT_MODEL` либо основная `LLM_MODEL`. Семантический поиск и embeddings пока не подключены.
- Альбомы Telegram сохраняются отдельными файлами без автоматического объединения. До создания события агент уточняет дальнейшие действия. Пересланная афиша сама по себе не означает намерение посетить мероприятие; правила описаны в [ATTACHMENTS.md](ATTACHMENTS.md).
- Сложные профили с несколькими рабочими окнами в день, исключениями каждого праздника и автоматической оптимизацией всей недели требуют расширения.
- Автономность действует внутри запроса пользователя и лимитов запуска. Самостоятельное формирование новых фоновых целей, неограниченное перепланирование, универсальный откат всех действий и графический редактор маршрута не реализованы. Интерфейс остаётся Telegram.
- Прерванный процесс возвращает сведения о сохранённых действиях; точное автоматическое продолжение внутреннего состояния SDK не гарантируется. Это не распределённая транзакция между PostgreSQL, Telegram и Google.
- Автоматическое восстановление QR-кодов, покупка/возврат билетов, бронирование и платежи отсутствуют.
- Реальные Telegram/Google/LLM вызовы и Docker-образы не проверены в среде подготовки. Установленные зависимости и локальные тесты проверены отдельно; см. [VERIFICATION.md](VERIFICATION.md).
- Уведомления об ошибках используют PostgreSQL и worker отправки. Они не заменяют проверку запуска контейнеров, загрузки `.env` и миграций; при недоступности БД или Telegram могут не доставиться. Подробности — [ERROR_REPORTING.md](ERROR_REPORTING.md).

Архитектура, режимы автономности и ограничения стоимости — [AGENT_ARCHITECTURE.md](AGENT_ARCHITECTURE.md).

Перед постоянным использованием выполните сценарии из [DEPLOY.md](DEPLOY.md), настройте резервирование и мониторинг. Логи проверки и тесты важнее заявленного статуса отдельного модуля; при изменении кода повторяйте затронутые проверки.
