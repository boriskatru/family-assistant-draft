# Задачи, памятные даты и занятость

## Как выбирать тип записи

| Смысл записи | Как сохраняется | Влияние на план |
|---|---|---|
| День рождения, годовщина, памятная дата | Событие на дату без часов | Видно в расписании; по умолчанию не занимает время |
| Поздравить, купить подарок, подготовить документы | Отдельная задача с оценкой длительности и, при необходимости, сроком | Планировщик может предложить время выполнения |
| Праздничная встреча, созвон, поездка с известным временем | Событие с началом и окончанием | По умолчанию занимает заданный интервал |
| Занятый день или несколько дней целиком | Событие на даты с явным признаком занятости | Занимает указанные дни |

День рождения не требует придуманного короткого интервала. Если пользователь сообщает только дату, агент сохраняет дату; время конкретного празднования можно добавить отдельным событием. Общая видимость записи и участие в ней остаются разными полями.

## Изменение существующих задач

Инструмент `update_task` позволяет менять название, описание, срок, приоритет, оценку и остаток минут, возможность разделения, категорию и состояние `todo` / `in_progress` / `cancelled`. Чтобы убрать срок, передаётся явное `clear_due_at=true`. Также доступны not_before (начать не раньше), исполнитель и участники, связи с проектом/поездкой/родителем, зависимости, видимость и область. clear_not_before снимает ограничение начала. Дедлайн задачи не является назначенным временем работы над ней.

Завершение выполняется отдельным `complete_task`, отмена завершения — update_task со status=todo или командой /undo_task. Перед изменением агент читает запись и её версию; устаревшая версия требует повторного чтения. Задачи с `visibility=shared` редактируют оба разрешённых супруга независимо от автора. Это не открывает им чужие личные задачи, проекты или файлы.

При изменении срока пересчитываются напоминания. Завершение и отмена задачи освобождают её будущие блоки, созданные планировщиком; изменение срока, начала, исполнителя и других условий отменяет устаревшие блоки для нового плана; самостоятельная встреча, лишь связанная с задачей, не удаляется.

## Исправление задачи, которая должна быть событием

`convert_task_to_event` в одной транзакции создаёт событие и переводит исходную задачу в `cancelled`. Задача сохраняется для истории и связана с событием через `task_id`; это не удаление записи и не фиктивное выполнение. По умолчанию переносятся название, описание, область, участники и связи с проектом/поездкой. Владелец и видимость сохраняются. Доступные отправителю вложения связываются с событием, но права самих файлов не меняются.

Перед преобразованием агент проверяет существующие события, чтобы не создать дубль. Проверка версии и журнал действий защищают от повторного применения одного поручения. Отдельные задачи, например «купить подарок», не являются исходной задачей преобразования и остаются самостоятельными.

Для ошибочной повторяющейся задачи сначала доступен stop_recurrence(cancel_future=false), затем преобразование исходной задачи. Преобразование всех экземпляров серии одной операцией пока не поддерживается. Также требуется сначала разрешить незавершённые зависимости. При этих препятствиях операция завершается без частичной записи. Для ежегодного повторения нового события используется `configure_recurrence` с годовым правилом; повторение задаётся по поручению пользователя.

## Даты, напоминания и календарь

Для новой записи без времени `create_event` принимает `all_day=true` и `start_date`; `starts_at` / `ends_at` не нужны. `end_date` не входит в период: если она не передана, событие длится один день. При переносе существующего многодневного события только по `start_date` сохраняется число дней. Эти поля доступны и через `update_event`.

`blocks_time` задаётся отдельно от дат и видимости:

- Новое событие на дату по умолчанию получает `false`: отображается, но не создаёт занятость.
- Новое событие с часами по умолчанию получает `true`.
- Пользователь может явно выбрать другой режим. При обычной правке существующей записи он сохраняется.

Свободные окна, дневная нагрузка и конфликты рассчитываются по событиям с `blocks_time=true`. Многодневные записи выводятся с датами начала и окончания; дата без времени не показывается как пяти- или пятнадцатиминутное дело. В Google Calendar признак занятости синхронизируется через `transparency`: `transparent` соответствует свободному времени, `opaque` — занятому. Google-события с датами остаются событиями на даты при импорте и экспорте.

Напоминание нового события на дату по умолчанию приходит в 09:00 первого дня по часовому поясу события. Если пользователь явно задал интервалы `remind_minutes`, они отсчитываются от начала первого дня, а не от 09:00. Пустой список отключает напоминания. Тихие часы и обычные правила доставки сохраняются.

## Отложенные дела в плане дня

Если задачу без срока или с будущим сроком не удалось разместить в выбранном дне, план учитывает её среди отложенных дел нейтральным счётчиком. Это не означает, что её срок нарушен. Неразмещённые задачи со сроком в этот день или раньше остаются в разделе, требующем внимания. Памятная дата без занятости не уменьшает доступное время для задач.

## Обновление и старые записи

Новая миграция `0004_event_blocks_time` добавляет признак занятости. Существующие события получают `true`, сохраняя прежнее поведение; миграция не угадывает, какие записи являются днями рождения. Сервис `migrate` в Docker Compose применяет миграцию перед запуском рабочих процессов. Порядок обновления — [DEPLOY.md](DEPLOY.md).

Установка обновления сама по себе не преобразует задачи на сервере. После неё можно отправить боту:

> Найди шесть задач с днями рождения и преобразуй их в события без времени на даты из текущих записей. Не занимай ими рабочее время. Перед созданием проверь дубли. Отдельную задачу о покупке подарка не меняй. Если исходная дата неоднозначна, уточни её.

Затем проверьте карточки созданных событий и план на соответствующие даты. Имена, даты и ID берутся из доступных записей и поручения пользователя; они не предзаполняются в коде.

## Нагрузка, напоминания и редактирование серий

`blocks_time` определяет занят ли интервал. Отдельное `counts_toward_load` управляет дневным лимитом: null автоматически исключает дорогу/проживание, true/false задают явное решение. `reset_load_policy=true` в update_event возвращает автоматический выбор. Пересекающиеся учитываемые интервалы объединяются.

`update_reminders` добавляет, удаляет, заменяет или выключает расписание напоминаний выбранного участника; `local_time=11:00` с нулевым смещением задаёт 11:00 в дату события. Отправленная история сохраняется; правка адреса/описания не повторяет доставку. Отключённое напоминание не включается при переносе.

`update_recurrence` изменяет будущую часть локальной серии с сохранением прошлых экземпляров и связанных документов/списков. `stop_recurrence` прекращает генерацию и по умолчанию отменяет будущие экземпляры; `cancel_future=false` сохраняет их. Импортированные Google-повторы остаются отдельными событиями.
