# Обновление: редактирование, планирование и общая история

## Что изменилось

| Сценарий | Поведение |
|---|---|
| Изменить совместное событие | Любой из двух разрешённых супругов может сразу менять детали, время, участников или отменять событие |
| Редактировать задачу | Доступны исполнитель, участники, проект/поездка, родитель, зависимости, срок, дата начала, оценка, видимость, возврат выполненной задачи |
| Изменить проект или поездку | Даты, описание, статус, участники; перенос всей поездки явно сдвигает связанные события |
| Исправить маршрут | Можно менять этап, статус брони, реквизиты и временные запасы |
| Изменить чек-лист | Добавление, правка, удаление пунктов, количество и исполнитель |
| Убрать неправильную привязку билета | Связь удаляется; оригинал и остальные связи сохраняются |
| Настроить напоминание | Добавление, удаление, замена, отключение; часы в день события, включая событие на дату |
| Изменить или остановить повторения | Изменяется будущая часть локальной серии; прошлые экземпляры сохраняются |
| Изменить время утреннего плана | Обычная просьба через read_preferences/update_preferences, без необходимости вводить команду |
| Продолжить обсуждение в группе | Единая история группы с авторами; личные диалоги и права на источники отделены |
| Прочитать Word/Excel | Локальное чтение DOCX/XLSX, без исполнения формул/макросов |
| Прочитать PDF со сканами и текстом | Модель получает оригинал; текст слоя и распознанный текст сохраняются отдельно и доступны вместе |

`not_before` у задачи означает «не начинать раньше», `due_at` — крайний срок. В календаре `blocks_time` означает занятость, `counts_toward_load` — участие в дневном лимите. При автоматическом выборе поездки и проживание занимают время, но не расходуют лимит нагрузки. Пересечения учитываются один раз. При завершении задачи освобождаются её будущие автоматические блоки; начатые/прошлые блоки и реальные связанные встречи сохраняются. Изменение условий задачи отменяет устаревшие будущие блоки для нового планирования.

Правка адреса или описания не повторяет отправленные напоминания. Отключённые напоминания остаются отключёнными после переноса. Общие Google-импорты включаются в планы обоих супругов; личные записи остаются личными, явное изменение участников сохраняется при следующей синхронизации.

## Установка существующего проекта

Архив содержит исходники, миграцию `0005_scheduling_bounds_and_load` и команду исправления старого состояния. Он не содержит ваших `.env`, базы, загруженных билетов и заполненного `private/personal_context.md`. Сохраните эти существующие данные при замене исходников. Перед обновлением сделайте обычную резервную копию.

Из каталога проекта на сервере, после распаковки новых исходников:

```bash
docker compose stop bot worker_chat worker_service worker_notifications scheduler
docker compose build
docker compose run --rm migrate
docker compose run --rm migrate python manage.py repair_schedule_state --apply
docker compose up -d --force-recreate bot worker_chat worker_service worker_notifications scheduler
```

Если включён веб-интерфейс Google OAuth, пересоздайте его тем же образом:

```bash
docker compose --profile web up -d --force-recreate app
```

`repair_schedule_state` без `--apply` показывает количество исправлений. С `--apply` он освобождает устаревшие будущие автоматические блоки и добавляет недостающих супругов к старым общим Google-импортам. Прямых запросов к Telegram/Google нет; изменения календаря ставятся в обычную очередь синхронизации. Повторный запуск не дублирует исправления. Команда не угадывает даты дней рождения и не преобразует произвольные задачи в события.

## Настройки выполнения агента

Новые параметры необязательны: при отсутствии используются указанные значения.

```dotenv
AGENT_MODEL_TIMEOUT_SECONDS=90
AGENT_MODEL_RETRIES=2
AGENT_MAX_CONTINUATIONS=2
```

`AGENT_HISTORY_USER_LIMIT` может быть больше 50; история всё равно помещается в общий бюджет запроса. После временной ошибки модели или исчерпания порции шагов возможны ограниченные автоматические продолжения с уже полученными результатами инструментов. Общие лимиты времени, токенов и инструментов не сбрасываются. Аварийное завершение процесса не обещает восстановление внутреннего состояния SDK: сохраняются выполненные действия и отчёт о них.

## Проверка после установки

1. От имени другого супруга измените описание общего события и его участников.
2. Попросите изменить срок и исполнителя задачи; проверьте новую карточку и освобождённые старые блоки.
3. Попросите добавить/удалить пункт существующего списка и отключить напоминание.
4. Измените время будущих повторений тестового события, затем остановите серию.
5. Продолжите обсуждение в группе репликой второго супруга; проверьте различение авторов.
6. Проверьте общий Google-импорт в планах обоих пользователей и загрузите тестовый DOCX/XLSX/PDF.

Реальные внешние сервисы и серверные данные не использовались при подготовке архива. Локальные проверки описаны в `VERIFICATION.md`.
