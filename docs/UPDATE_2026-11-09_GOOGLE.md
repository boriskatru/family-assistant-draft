# Исправление синхронизации Google и диагностики — 09.11.2026

## Что установлено по уведомлениям

- `dc65cf6cf405`, задание `6fdbaad5-90cf-4b0a-9d13-102e5b3c6175`: Google отклонил PATCH существующего события. В прежней версии HTTP-статус и код причины терялись при подготовке отчёта. По одному стеку нельзя определить, были ли причиной данные события, права или лимиты.
- `465afcd935ec`, задание `39a49261-1024-48c0-ad69-ec30c3c45409`: общий проход синхронизации завершился с ошибками. Раньше любая ошибка внутри него превращалась в GoogleRetryableError, поэтому название исключения не доказывает временный сбой Google. Эти два уведомления могут относиться к одной проблеме, но подтвердить это по ним нельзя.

## Исправления

1. При переводе события со временем в событие на дату и обратно PATCH явно удаляет прежние несовместимые поля `date`/`dateTime`. Иначе Google объединял вложенные поля и получал некорректный интервал. Гости, конференция и остальные сторонние поля сохраняются; контроль версии ETag остаётся.
2. HTTP-статус, известный код причины Google и операция сохраняются в безопасной диагностике. Тело ответа, названия событий, адреса, календарные идентификаторы и токены не выводятся.
3. Ошибки `403 rateLimitExceeded` и `userRateLimitExceeded` повторяются, как и HTTP 429/5xx. Постоянные отказы Google завершают текущее задание без пяти одинаковых попыток. Обычная периодическая синхронизация продолжает работать.
4. Временные ошибки фонового задания записываются в лог без уведомления на каждой попытке; после исчерпания пяти попыток приходит отчёт. Для одинаковых отчётов сохраняется установленный интервал подавления повторов.
5. Общая синхронизация продолжает обрабатывать остальные записи и сохраняет исходную причину, количество ошибок и число временных отказов. Постоянные ошибки больше не объявляются временными без основания. При смешанном результате повторяются попытки полного прохода, чтобы восстановить временно неудавшиеся операции.
6. Ошибка настроек OAuth-клиента больше не отключает пользовательское подключение. Оно отключается при подтверждённом `invalid_grant`. Запоздалый HTTP 401 от одного worker не затирает токены, уже обновлённые другим.

## Обновление VPS

Замените исходники содержимым архива в текущем каталоге проекта, сохранив существующие `.env`, `private`, базу и тома Docker. Этот выпуск не добавляет миграций. Если предыдущие обновления ещё не установлены, обычный migrate применит недостающие миграции из архива.

```bash
docker compose stop bot worker_chat worker_service worker_notifications scheduler
docker compose build
docker compose run --rm migrate
docker compose up -d --force-recreate bot worker_chat worker_service worker_notifications scheduler
```

Если работает веб-интерфейс OAuth:

```bash
docker compose --profile web up -d --force-recreate app
```

Повторная авторизация для установки обновления не требуется. Сохраняйте прежний `TOKEN_ENCRYPTION_KEY` и OAuth-настройки. Уже отключённое подключение этот выпуск автоматически не включает: сначала нужно установить причину отключения.

Обычная синхронизация снова проверит связанные и ожидающие записи. Создавать их заново не нужно. Сервер и реальный Google-аккаунт при подготовке архива не изменялись; точная причина двух исторических отказов остаётся неустановленной.

## Проверка задания без раскрытия данных

После обновления можно посмотреть состояние указанных заданий:

```bash
docker compose exec worker_service python manage.py job_diagnostics 6fdbaad5-90cf-4b0a-9d13-102e5b3c6175 39a49261-1024-48c0-ad69-ec30c3c45409
```

Команда только читает базу: статус, число попыток и безопасные поля ошибки. Старые задания могут содержать лишь класс исключения; отсутствующий HTTP-код восстановить из него невозможно. У успешно завершившегося задания поле ошибки очищается. При новом сбое новый отчёт уже будет содержать доступные HTTP-код, причину и операцию.
