# Отчёт проверки чернового проекта

Дата обновления: 4 ноября 2026. Это проверка исходников в среде подготовки, не отчёт о запуске на вашем VPS.

## Выполнено

- Python 3.12: зависимости установлены по `requirements.lock`; `pip check` — без конфликтов.
- `pytest -q` — **194 passed**, локальная тестовая БД SQLite. Telegram, Google, карты и ответы модели заменены тестовыми данными; реальные сообщения не отправлялись.
- OpenAI Agents SDK 0.24.0 выполнялся реально с подменённой моделью: проверены цепочка `search → create → read → answer`, возврат наблюдений модели, ограничения шагов/инструментов/токенов, частичные результаты после сбоя и отсутствие экспорта SDK-трасс.
- Проверены атомарные записи и квитанции действий, восстановление после прерывания, повторные вызовы, изменение автономности, сохранность ACL-ссылок при сбое и запрет выдачи личных документов другому пользователю.
- Внешний HTTP-транспорт проверен через настоящий HTTP-парсер и `httpcore.MockBackend`: публичные IP, Host/TLS SNI, защита от DNS rebinding, перенаправления, общий дедлайн, ограничения объёма. Google Places/Routes и веб-поиск проверены с подменёнными ответами.
- PDF: реальный отдельный процесс прочитал тестовый документ; проверены пределы страниц/символов, обработка некорректного PDF и таймаута без раскрытия исходного текста в ошибках.
- Проверены блокировки известных ключей API и распознанных идентификаторов документов в публичных запросах. Это ограниченная защита, не исчерпывающий тест всех вариантов prompt injection.
- `manage.py check` — `System check identified no issues`.
- `manage.py makemigrations --check --dry-run` — `No changes detected`.
- Чистая временная БД: успешно выполнены миграции, `bootstrap_users`, один цикл scheduler и два запуска worker. Задания recurrence и google_sync завершились; подключённых внешних аккаунтов в этом прогоне не было.
- Переход `0001 → 0002` отдельно выполнен на временной БД: созданная до обновления задача сохранилась, новые таблицы агента доступны, scheduler и оба служебных задания завершились.
- Python-файлы компилируются; синтаксис shell-скриптов проверен через `bash -n`.
- YAML Compose и GitHub Actions разобран; проверены службы, отсутствие публичного порта PostgreSQL и включение lockfile в Dockerfile.
- Генератор `.env`: проверены случайные ключи, права 600, отсутствие секретов в stdout и отказ перезаписи.
- Restore: проверен отказ от архивов с обходом путей и небезопасными типами записей до изменения конфигурации.

## Основные тестируемые сценарии

Права private/shared/busy_only; отдельные права документов и вложенных участков поездки; повторная проверка доступа перед отправкой отложенного ответа; согласование общих событий; сохранение оригиналов и отметок чек-листа; дедупликация Telegram updates; аренда заданий и защита от завершения старым worker; тихие часы и пропущенные напоминания; перенос после отправленного напоминания; устаревшие подтверждения; планирование с зависимостями и повторной проверкой занятости; RRULE, смены и повтор после выполнения; OAuth state, шифрование, конфликты Google и получение Meet; строгие допустимые действия LLM.

## Не проверено здесь

- Сборка и запуск Docker Compose: Docker в среде подготовки отсутствует.
- Выполнение на PostgreSQL и конкурентная работа нескольких процессов с его блокировками. В архиве есть GitHub Actions workflow с PostgreSQL и сборкой Docker; он подготовлен, но не запускался в GitHub.
- Реальные Telegram, Google Calendar/Meet, Google Maps, Brave/OpenAI web search и LLM API, домен, сертификаты, права конкретных аккаунтов и сетевой доступ VPS.
- Полный цикл backup/restore с работающими контейнерами и реальными volumes.

Первый запуск выполняется по [DEPLOY.md](DEPLOY.md). Ограничения функциональности описаны в [STATUS.md](STATUS.md). Успешные локальные тесты не заменяют проверку с вашими двумя аккаунтами.
