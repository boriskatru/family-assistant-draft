# Отчёт проверки чернового проекта

Дата обновления: 5 ноября 2026. Это проверка исходников в среде подготовки, не отчёт о запуске на вашем VPS.

## Выполнено

- Python 3.12: зависимости установлены по `requirements.lock`; `pip check` — без конфликтов.
- Последний локальный `pytest -q` на SQLite завершился с результатом **457 passed, 3 skipped**. Пропущены три проверки конкурентной записи через реальные сессии PostgreSQL: истории чата, общей адресной карточки и подавления повторных диагностических уведомлений.
- Исправлен неподдерживаемый `format: uri` в `create_event.meeting_url`; проверка URL на стороне приложения сохранена. Девять новых проверок охватывают форматы всех 30 инструментов, воспроизведение отказа старой схемы на приветствие, успешные запросы с исправленной схемой и сохранение/отклонение ссылок. Используется реальный SDK с локальной HTTP-заглушкой, которая проверяет допустимые форматы: это не проверка живого API.
- Проверены ошибки API через настоящий Agents SDK с HTTP-заглушкой: короткий ответ с кодом в исходном чате и отдельная безопасная диагностика только настроенному администратору в личку. Проверены отзыв прав перед доставкой, подавление повторов, сбой очереди, ошибки polling/worker/scheduler и отсутствие рекурсивных уведомлений.
- Проверены запросы после 49, 50, 51 и 100 обменов: ограничение памяти работает как скользящее окно, а не лимит использования. Эти проверки не используют живой API; конкретная причина сбоя на VPS требует его логов или диагностического отчёта.
- Проверены оба направления создания событий на двоих через Telegram и инструмент агента, напоминания каждому, уведомление второго участника без кнопок, принятие совместного блока плана, повторения и прежнее согласование переноса. Для старых заявок проверены предварительный просмотр, активация подходящих событий и повторный запуск команды.
- На aiogram 3.31.0 воспроизведена ошибка сериализации сообщения с предпросмотром ссылки. В тесте ответа Telegram Bot API после исправления сохраняются исходные поля ссылки, подпись пересланного фото и следующая команда `/id`. При сбое записи в БД следующее чтение начинается с неподтверждённого сообщения.
- Для пересланной афиши проверены получение подписи из Telegram, сохранение полного текста при сбое OCR, чтение карточки, поиск, повторная выдача и доступ к разным подписям одного изображения. Команда восстановления проверена на старых обновлениях и квитанциях, включая повторный запуск и пропуск неоднозначных совпадений.
- Воспроизведена потеря отправителя при сериализации полученного через polling объекта aiogram. После исправления тест проводит новый `/start` от объекта `Update` через сохранение входящего сообщения и обе очереди до вызова `sendMessage`. Сетевой обмен с Telegram подменён. Отдельно проверены прежний формат очереди и определение автора нажатия на кнопку.
- OpenAI Agents SDK 0.24.0 выполнялся реально с подменённой моделью: проверены цепочка `search → create → read → answer`, возврат наблюдений модели, ограничения шагов/инструментов/токенов, частичные результаты после сбоя и отсутствие экспорта SDK-трасс.
- Проверены атомарные записи и квитанции действий, восстановление после прерывания, повторные вызовы, изменение автономности, сохранность ACL-ссылок при сбое и запрет выдачи личных документов другому пользователю.
- Внешний HTTP-транспорт проверен через настоящий HTTP-парсер и `httpcore.MockBackend`: публичные IP, Host/TLS SNI, защита от DNS rebinding, перенаправления, общий дедлайн, ограничения объёма. Google Places/Routes и веб-поиск проверены с подменёнными ответами.
- PDF: реальный отдельный процесс прочитал тестовый документ; проверены пределы страниц/символов, обработка некорректного PDF и таймаута без раскрытия исходного текста в ошибках.
- Проверены блокировки известных ключей API и распознанных идентификаторов документов в публичных запросах. Это ограниченная защита, не исчерпывающий тест всех вариантов prompt injection.

- Чистая временная БД: успешно выполнены миграции, `bootstrap_users`, один цикл scheduler и два запуска worker. Задания recurrence и google_sync завершились; подключённых внешних аккаунтов в этом прогоне не было.

- Python-файлы компилируются; синтаксис shell-скриптов проверен через `bash -n`.

## Общие права редактирования (5 ноября 2026)

- Оба разрешённых супруга могут редактировать существующие shared-события/поездки без назначения editors. Проверены чек-листы, отметки, привязка собственных документов и участков; сценарии агента выполнены в личном и настроенном общем чате в обоих направлениях авторства.
- Проверены запреты private/busy_only, независимые права документов/проектов/задач, отзыв разрешённого ID, возврат записи в личную видимость и отказ применять ожидающее согласование после отзыва прав инициатора. Согласование изменений общей встречи сохранено.
- Второй супруг может настроить повторения общего события с участием обоих. Проверены исходный владелец будущих экземпляров, отдельные чек-листы, напоминания обоим и отсутствие дублей при повторной материализации.
- Голые `/show` и `/attach` могли вызвать `not enough values to unpack`; теперь проверяются аргументы и отправляется подсказка, некорректный `/attach` не сохраняет файл. По скриншоту нельзя установить, какая именно команда вызвала ошибку. Проверены повторная доставка команды и адресованные команды с пробелом/табуляцией/переносом строки.
- Полный локальный прогон: **348 passed, 1 skipped**, SQLite. Django check и проверка отсутствия новых миграций прошли. PostgreSQL и внешний Telegram здесь не запускались; прогон PostgreSQL 16 предусмотрен в GitHub Actions. Изменения модели/миграции данных не нужны.

## Основные тестируемые сценарии

Права private/shared/busy_only; отдельные права документов и вложенных участков поездки; повторная проверка доступа перед отправкой отложенного ответа; согласование общих событий; сохранение оригиналов и отметок чек-листа; дедупликация Telegram updates; аренда заданий и защита от завершения старым worker; тихие часы и пропущенные напоминания; перенос после отправленного напоминания; устаревшие подтверждения; планирование с зависимостями и повторной проверкой занятости; RRULE, смены и повтор после выполнения; OAuth state, шифрование, конфликты Google и получение Meet; строгие допустимые действия LLM.

## Исправление после первого прогона GitHub Actions

- В присланном логе PostgreSQL: 191 тест прошёл, 3 упали из-за одного запроса чек-листа — `FOR UPDATE cannot be applied to the nullable side of an outer join`.
- В `assistant/services.py` блокировка ограничена строкой `ChecklistItem` через `select_for_update(of=('self',))`. Необязательные связи события и поездки по-прежнему читаются; повторная проверка прав и идемпотентность отметок сохранены.
- В `tests/conftest.py` добавлено закрытие соединений Django внутри постоянного потока `sync_to_async` до удаления тестовой БД. Это устраняет источник предупреждения о занятой БД, не подавляя само предупреждение.
- После исправления полный локальный прогон: **194 passed**, SQLite; три упавших сценария также прошли отдельно. Django check и проверка миграций успешны.
- Компилятор PostgreSQL Django сформировал запрос с прежними `LEFT OUTER JOIN` и окончанием `FOR UPDATE OF "assistant_checklistitem"`. Это проверка SQL без подключения к серверу, не выполнение на PostgreSQL.
- Для обновления репозитория достаточно заменить `assistant/services.py` и `tests/conftest.py` из архива, сделать commit/push и дождаться нового GitHub Actions. Новые миграции не требуются.

## Память, лимиты и кэш

- Проверено окно из 50 пользовательских сообщений с учётом текущего запроса, чтение прежнего формата, сокращение истории целыми парами при нехватке бюджета и разделение диалогов. Тесты охватывают отзыв доступа и защиту данных документа при их повторном использовании в разговоре.
- Через настоящий Agents SDK и HTTP-транспорт с подменённым ответом проверены JSON запросов Luna и Terra, стабильность ключа кэша для диалога, `store=False`, TTL 30 минут и 12 часов, настройка effort и счётчик кэша в Telegram. Живые попадания в кэш проверяются на VPS по `/agent_history`.
- Проверено, что значения из окружения выше прежних жёстких пределов доходят до SDK. Кэшированные токены входят в общий расход один раз.
- В GitHub Actions предусмотрена отдельная проверка одновременной записи двух обменов через независимые подключения к PostgreSQL 16. В среде подготовки отсутствует доступный сервер PostgreSQL для этого прогона.

## Не проверено здесь

- Сборка и запуск Docker Compose: Docker в среде подготовки отсутствует.
- Успешный полный прогон на PostgreSQL после исправления, отсутствие предупреждения при удалении его тестовой БД и конкурентная работа нескольких процессов с блокировками. Для повторной проверки в архиве есть GitHub Actions workflow с PostgreSQL и сборкой Docker.
- Реальные Telegram, Google Calendar/Meet, Google Maps, Brave/OpenAI web search и LLM API, домен, сертификаты, права конкретных аккаунтов и сетевой доступ VPS.
- Полный цикл backup/restore с работающими контейнерами и реальными volumes.

Первый запуск выполняется по [DEPLOY.md](DEPLOY.md). Ограничения функциональности описаны в [STATUS.md](STATUS.md). Успешные локальные тесты не заменяют проверку с вашими двумя аккаунтами.
