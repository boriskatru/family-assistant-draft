## Основные тестируемые сценарии

Права private/shared/busy_only; отдельные права документов и вложенных участков поездки; повторная проверка доступа перед отправкой отложенного ответа; непосредственное редактирование общих событий и подтверждение создания события только для другого супруга; сохранение оригиналов и отметок чек-листа; дедупликация Telegram updates; аренда заданий и защита от завершения старым worker; тихие часы и пропущенные напоминания; перенос после отправленного напоминания; устаревшие подтверждения; планирование с зависимостями и повторной проверкой занятости; RRULE, смены и повтор после выполнения; OAuth state, шифрование, конфликты Google и получение Meet; строгие допустимые действия LLM.

## Исправление после первого прогона GitHub Actions

- В присланном логе PostgreSQL: 191 тест прошёл, 3 упали из-за одного запроса чек-листа — `FOR UPDATE cannot be applied to the nullable side of an outer join`.
- В `assistant/services.py` блокировка ограничена строкой `ChecklistItem` через `select_for_update(of=('self',))`. Необязательные связи события и поездки по-прежнему читаются; повторная проверка прав и идемпотентность отметок сохранены.
- В `tests/conftest.py` добавлено закрытие соединений Django внутри постоянного потока `sync_to_async` до удаления тестовой БД. Это устраняет источник предупреждения о занятой БД, не подавляя само предупреждение.
- После исправления полный локальный прогон: **194 passed**, SQLite; три упавших сценария также прошли отдельно. Django check и проверка миграций успешны.
- Компилятор PostgreSQL Django сформировал запрос с прежними `LEFT OUTER JOIN` и окончанием `FOR UPDATE OF "assistant_checklistitem"`. Это проверка SQL без подключения к серверу, не выполнение на PostgreSQL.
- Для обновления репозитория достаточно заменить `assistant/services.py` и `tests/conftest.py` из архива, сделать commit/push и дождаться нового GitHub Actions. Новые миграции не требуются.

## Память, лимиты и кэш

- Проверено окно из 50 пользовательских сообщений с учётом текущего запроса, чтение прежнего формата, сокращение истории целыми парами при нехватке бюджета и разделение диалогов. Тесты охватывают отзыв доступа и защиту данных документа при их повторном использовании в разговоре.
- Через настоящий Agents SDK и HTTP-транспорт с подменённым ответом проверены JSON запросов Luna и Terra, стабильность ключа кэша для диалога, `store=False`, TTL 30 минут и 12 часов, настройка effort и счётчик кэша в Telegram. Живые попадания в кэш проверяются на VPS по `/agent_history`.
- Проверено, что значения из окружения выше прежних жёстких пределов доходят до SDK. Кэшированные токены входят в общий расход один раз.
- В GitHub Actions предусмотрена отдельная проверка одновременной записи двух обменов через независимые подключения к PostgreSQL 16. В среде подготовки отсутствует доступный сервер PostgreSQL для этого прогона.

- Реальные Telegram, Google Calendar/Meet, Google Maps, Brave/OpenAI web search и LLM API, домен, сертификаты, права конкретных аккаунтов и сетевой доступ VPS.
- Полный цикл backup/restore с работающими контейнерами и реальными volumes.
